## 1. Definition of Workflow

| Колонка | Картка потрапляє сюди, коли | Картка виходить звідси, коли |
| --- | --- | --- |
| Backlog | Завдання визначене, але ще не готове до виконання або не має пріоритету для старту | Визначено результат, критерії завершення та завдання можна брати в роботу |
| Ready | Завдання має чіткий результат, зрозумілі критерії завершення та достатній обсяг інформації для виконання | Виконавець починає роботу над завданням |
| In progress | Роботу над завданням фактично розпочато | Результат виконаний і переданий на перевірку |
| Review | Результат виконаний і доступний для перевірки | Перевірку пройдено або завдання повернуто на доопрацювання |
| Done | Завдання пройшло перевірку, а результат відповідає визначеним критеріям завершення | Картка залишається завершеною |

## 2. WIP-ліміти

| Колонка | Ліміт | Чому саме такий |
| --- | :-: | --- |
| In progress | 3 | Обмеження кількості одночасних завдань допомагає уникнути перемикання між багатьма роботами |
| Review | 2 | Дозволяє не накопичувати завдання на перевірці та швидше завершувати розпочату роботу |

Що ви робите, коли ліміт вичерпано:

Не починаю нову картку. Спочатку завершую або просуваю завдання, які вже перебувають у відповідній колонці. Якщо ліміт Review вичерпаний, зосереджуюся на перевірці наявних результатів.

Коли ліміт спрацював:

`Очікує фактичного спрацювання WIP-ліміту: ключ картки, дата та виконана замість старту дія.`

## 4. Конверт 1, зменшення ліміту

Стан дошки до конверта:

`Буде записано безпосередньо перед відкриттям конверта.`

Що сталося після зменшення ліміту:

`Буде заповнено після фактичного зменшення WIP-ліміту.`

Що ви зробили, коли вперлися в ліміт:

`Буде заповнено після першого фактичного спрацювання ліміту.`

Чи змінилась швидкість завершення і як ви це побачили:

`Буде визначено за фактичними датами завершення карток.`

## 5. Конверт 2, термінова картка

Стан дошки до конверта:

`Буде зафіксовано перед відкриттям другого конверта.`

Що зупинили, щоб пропустити термінову картку:

`Буде заповнено після фактичного запуску expedite-картки.`

Скільки вона зайняла від появи до завершення:

`Буде визначено за реальними датами появи та завершення.`

Що робимо, якщо таких карток стане три на тиждень:

Якщо термінові завдання почнуть з'являтися регулярно, вони можуть витіснити планову роботу та знизити передбачуваність потоку. Доцільно встановити окремий ліміт на expedite-завдання та приймати їх лише за наявності обґрунтованої терміновості. Регулярні термінові завдання потрібно аналізувати, щоб усунути причину їх появи.

## 6. Перший вимір

| Показник | Значення |
| --- | :-: |
| Найкоротший cycle time, днів | Очікує завершення карток |
| Найдовший cycle time, днів | Очікує завершення карток |
| Середній cycle time, днів | Очікує завершення карток |
| Завершених карток у вимірі | 0 на момент початку роботи |

Колонка, у якій картки чекали найдовше, і чому саме там:

`Буде визначено за фактичною історією переміщення карток.`

Якщо завершених карток менше восьми, чому їх мало:

`Буде заповнено після завершення двотижневого періоду.`
