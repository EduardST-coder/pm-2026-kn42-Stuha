Файл `dod.md` містить **8 перевірюваних умов**.

## 4. Технічний борг

| Поле | Значення |
| --- | --- |
| Записів у `techdebt.csv` | 3 |
| Разом годин на повернення | 30 |
| Стеля годин мого варіанта | 1680 |
| Борг у відсотках від стелі | 1,79% |
| Рішення pay_now / pay_later / accept | 0 / 2 / 1 |

Розрахунок: 30 / 1680 × 100 = **1,79%**.

Технічний борг виник через свідоме обмеження першого релізу. Розширене керування життєвим циклом сесій та аналітичний інтерфейс журналу доступу відкладено до REL-2. Для сторінки прозорості даних у REL-1 використовується конфігураційний перелік без окремого автоматизованого механізму його обслуговування.

Свідомо прийнято D-03: ручне оновлення конфігураційного переліку строків зберігання. Це дозволяє виконати обов'язкову вимогу першого релізу без додаткової автоматизації, яку можна оцінити після початкової експлуатації.

Для замовника цей борг означає, що перша версія матиме необхідні функції доступу, аудиту та прозорості даних, але розширене керування сесіями, аналітика журналу й автоматизація окремих операцій потребуватимуть додаткових робіт у наступному релізі.
