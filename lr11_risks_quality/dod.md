# Definition of Done

Студент: Стуга, EduardST-coder. 
Тема: Мобільний застосунок розкладу академії з повідомленнями про зміни.

## Умови, за яких історія вважається завершеною

- Реалізація відповідає критеріям приймання відповідної історії з беклогу.
- Код перевірено автором за допомогою перегляду змін і перевірки на очевидні помилки.
- Для реалізованої функціональності виконано відповідні ручні або автоматизовані перевірки; критичних помилок не виявлено.
- Зміни інтегровано в основну гілку репозиторію GitHub без конфліктів.
- Для функцій, що працюють із персональними даними, виконано відповідні вимоги безпеки та доступу.
- Оновлено README або іншу документацію, якщо змінилися інструкції запуску, налаштування чи використання функціональності.

## Чого DoD свідомо не вимагає

- Обов'язкового code review другою людиною: проєкт виконується одним студентом, тому його замінює самоперевірка коду та перевірка працездатності.
- Фіксованого відсотка покриття автоматизованими тестами для кожної історії: обсяг тестування визначається ризиком і складністю функціональності.

## Як це працює на практиці

Скільки історій, закритих у ваших спринтах, справді пройшли цей DoD: **0 з 4**.

Наявні на дошці закриті історії S-02, S-03, S-04 та S-06 не мають достатніх підтверджень виконання всіх умов DoD, тому їх не зараховано як такі, що доведено пройшли Definition of Done. Повторна перевірка та підтвердження виконання умов мають відбутися перед остаточним прийманням.

## Хто ухвалює відхилення від DoD

Відхилення від DoD може погодити спонсор проєкту після письмового обґрунтування PM; рішення та причина фіксуються в журналі змін, а невиконана умова реєструється як технічний борг у `techdebt.csv`. Вимоги інформаційної безпеки не можуть бути скасовані таким відхиленням.
